# Режимы Update и Audit

Правила гриллинга те же, что в Create: один вопрос, рекомендация первой, всё кликабельно, факты ищешь сам, ничего не меняешь до подтверждения сводки.

## Update — `/crazymgt:agent-creator update <name>`

Цикл обслуживания гл. 18: наблюдаем → замечаем → разбираем → обновляем → проверяем → записываем.

1. **Загрузка.** Найди Pack: `.claude/agent-packs/<name>/`, затем `~/.claude/agent-packs/<name>/`. Прочитай `00-README.md`, `_grilling-log.md`, `validation-report.md`, `failure-log.md`, `context-update-log.md` (если есть) и файл агента. Pack не найден → предложи режим Audit для файла агента.
2. **Сигнал.** Первый вопрос: что изменилось или что не так. Варианты собирай из фактов: открытые 🟡 в README, провалы из failure-log, сигналы из `17-maintenance.md`, плюс «процесс или правила изменились» и «новый tool или источник».
3. **Диагноз слоя** (гл. 18, «не каждый инцидент лечится промптом»). Вопрос: какой слой меняем — источник, роль, workflow, tool contract, approval, memory, домен, evals, handoff. [R] Слой, на который указывает сигнал. Промпт — последним.
4. **Точечный гриллинг.** Только узлы `question-tree.md`, затронутые изменением, плюс узлы, которые от них зависят. Если ответ включает новый модуль, проходи его узлы целиком.
5. **Сводка изменений → подтверждение.** Diff по файлам Pack и агента в виде «было → станет».
6. **Применение.** Правка Pack → пересборка агента → запись в `context-update-log.md`:

```markdown
## <YYYY-MM-DD> — <кратко>
- Сигнал: …
- Что изменили: … (файлы: 05, 06, агент)
- Слой: source | role | workflow | tool | approval | memory | domain | eval | handoff | prompt
- Почему: …
- Как проверили: Regression — GT-1, GT-3, GT-новый
- Результат: …
- Следующий пересмотр: <дата>
```

7. **Regression.** Прогони `validation.md`, этап 2: все stop/approval-задачи плюс задачи, затронутые изменением, плюс одна старая обычная. Минимум по гл. 18: обычные сценарии, один рискованный, один на stop rule, один на устаревший или конфликтный источник. Если новый случай не покрыт, добавь его в Golden Tasks.
8. Увеличь «Версия Pack» в README и обнови статусы.

## Audit — `/crazymgt:agent-creator audit <path>`

Для агента или skill, сделанного без Agent-Creator, или для проверки чужого.

1. **Чтение.** Прочитай файл целиком: frontmatter и тело. Если рядом есть Pack — прочитай и его.
2. **Маппинг на Pack.** Для каждого артефакта ядра определи: явно есть / частично / нет. Ищи по смыслу, а не по заголовкам (stop rule может быть фразой «если не уверен — спроси»).
3. **Красные флаги** (из шаблонов, гл. 5, 10, 12, 15):
   - роль «на всё», нет блока «не делает»;
   - tools без ограничений, лишние tools (excessive agency), send/delete в subagent;
   - нет источника истины или правила конфликта;
   - нет stop rules или approval для внешних действий;
   - нет формата отчёта и критерия готовности;
   - нет защиты от prompt injection при работе с внешним текстом;
   - `description` без «не используй для».
4. **Gap Report** (показать пользователю, в файлы не писать до подтверждения):

```markdown
# Audit — <агент>
| Артефакт | Статус | Где в файле | Риск при отсутствии |
|---|---|---|---|
| Role Card: не-задачи | ❌ | — | агент возьмёт задачу шире роли |
| Tool Contract | 🟡 | tools: Bash, Write | нет scope записи |

## Красные флаги
1. … (риск, глава)

## Рекомендация
<дособрать Pack | точечно поправить агента | пересобрать с нуля>
```

5. **Выбор пути** — AskUserQuestion:
   - `Дособрать Pack и пересобрать агента (Recommended)` — гриллинг только по ❌/🟡 узлам, существующее содержимое агента используется как готовые ответы (подтверждается одним вопросом на артефакт), затем стандартные Шаги 3–5 Create;
   - `Только исправить красные флаги` — минимальные правки агента без Pack;
   - `Только отчёт` — сохранить Gap Report и закончить.
6. Исходный файл агента перед перезаписью сохрани рядом как `<name>.md.bak-<дата>`.
