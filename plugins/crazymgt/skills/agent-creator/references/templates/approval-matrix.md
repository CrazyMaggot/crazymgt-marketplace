# Action Approval Matrix (гл. 5, 10, 15)

**Назначение:** явно разделить, что агент делает сам, что только черновиком, а что — только после человека. Approval — не недоверие к агенту, а граница ответственности.
**Узлы гриллинга:** A1, A2, D2, R3, T2.

## Шаблон

```markdown
# Action Approval Matrix — <агент>
Связано: 02, 04, 05

| Класс | Действия этого агента | Кто выполняет | Approval |
|---|---|---|---|
| Read-only | <прочитать вход, найти правило, проверить источник> | агент | не нужен |
| Draft | <подготовить черновик, список вопросов, план> | агент | не нужен |
| Internal write | <сохранить в разрешённое поле или папку> | агент | <нужен / не нужен + условие> |
| External send / publish | <отправить, опубликовать, прокомментировать> | человек (агент готовит) | всегда |
| Irreversible / money / delete | <удалить, оплатить, изменить права, перезаписать> | только человек | агент готовит план |

## Обязательный approval (всегда)
Деньги · договоры · юридические обещания · публикация наружу · отправка клиенту · удаление · изменение прав доступа · персональные данные · действия без лёгкого отката · команды, которые могут сломать систему.

## Как запрашивается approval
- Subagent: остановиться → Return Report со `status: needs_approval` + точное действие (что, куда, с каким содержимым) + почему нужно + риски.
- Skill: показать действие целиком → AskUserQuestion. `(Recommended)` на «Подтвердить» только при пройденных checks.

## Что агент возвращает вместо действия
<формат: черновик + «нужно approval: да» + риск + следующий шаг>
```

## Критерии качества
Draft отделён от send · у каждого опасного действия есть approval boundary · необратимое агенту не доступно · форма запроса approval соответствует форме агента · матрица не противоречит Role Card (R3) и Tool Contract (T2).

## Красные флаги
«Если что — спроси» без перечня действий · send разрешён, потому что «это удобно» · агент «имитирует отправку» · approval есть в тексте, но tool отправки выдан subagent.
