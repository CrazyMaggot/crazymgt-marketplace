# Agent Task Brief (гл. 3)

**Назначение:** превратить сырой запрос в рабочую карточку задачи, чтобы агент не гадал. Это prompt, ставший структурой.
**Узлы гриллинга:** P1–P4, R1, R7, S1, R3, T1.

## Шаблон

```markdown
# Agent Task Brief — <агент>
Связано: 02, 03, 04, 05, 07

1. **Роль агента:** <кем агент является в этой задаче — функция, а не персона>
2. **Задача:** <что именно нужно сделать>
3. **Зачем это нужно:** <для какого решения, действия или результата>
4. **Контекст:** <что агент должен знать перед работой>
5. **Вход (trigger + минимум):** <что запускает; без чего не начинать>
6. **Источники:** <на что опираться — ссылка на 03>
7. **Ограничения:** <что нельзя делать, обещать, менять, публиковать>
8. **Инструменты:** <какими tools пользоваться — ссылка на 04>
9. **Формат результата:** <как выглядит результат>
10. **Критерий готовности:** <как понять, что результат можно принять>
11. **Правило остановки:** <когда остановиться и попросить уточнение>
```

## Критерии качества
- Задачу можно понять без дополнительных объяснений.
- Роль помогает выполнить задачу, а не украшает её.
- Есть контекст, а не только просьба.
- Ограничения, формат, критерий готовности и stop rule — на месте.
- Если нет трёх и более пунктов — это ещё не задание агенту, а просто запрос.

## Красные флаги
- «Сделай хорошо / красиво» вместо формата и критерия.
- «Ты гениальный эксперт мирового уровня» вместо функциональной роли.
- Нет правила остановки: агент будет фантазировать при нехватке данных.

## Мини-пример (уровень детализации, не копировать)
Роль: агент аналитики клиентских обращений. Задача: черновик еженедельного отчёта по обращениям. Источники: тикеты за 7 дней, шаблон отчёта, прошлый отчёт. Ограничения: не отправлять команде, не менять тикеты, не раскрывать ПДн. Готовность: видно, какие данные использованы, где вывод, где риск, где нужен человек. Стоп: нет доступа к тикетам или шаблону — не придумывать, сказать, какого доступа не хватает.
