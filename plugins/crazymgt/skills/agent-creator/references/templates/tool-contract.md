# Tool Contract + Tool Risk Checklist + Tool Test Set (гл. 10, 12)

**Назначение:** инструмент без правил — риск, инструмент с контрактом — управляемое действие. MCP — способ подключения, а не гарантия безопасности.
**Узлы гриллинга:** T1–T3, A1.

## Tool Risk Checklist (задавай себе по каждому tool до T3)
Что делает? · чтение или изменение? · какие системы затрагивает? · какие данные видит? · есть ли ПДн? · есть ли деньги, договоры, права, публичная отправка? · минимальный scope? · где approval? · как проверить результат? · как откатить? · что логировать и что нельзя? · что делать при ошибке? · что делать при неуверенности?
Нет ответов — инструмент рано давать агенту.

## Маппинг на Claude Code
- read-only: Read, Grep, Glob, WebFetch, WebSearch, read-методы MCP.
- draft: Write в ограниченную папку черновиков.
- write: Edit, Write вне drafts, write-методы MCP, Bash (по умолчанию).
- send/publish: MCP-методы send/post/publish/comment, Bash с сетевыми командами, `git push`.
- delete/pay/irreversible: удаление файлов и записей, платежи, `rm`, `git reset --hard`, изменение прав.
- Bash выдаётся только с перечнем разрешённых команд в контракте.

## Красные флаги
«Дадим полный доступ» · tool делает слишком много (`update_crm(anything)`) · нет схемы входов · нет описания ошибок · нет approval на отправку, удаление, деньги · нет логов · отправка наружу без показа текста · запись без проверки target · «успех» без проверки результата.
