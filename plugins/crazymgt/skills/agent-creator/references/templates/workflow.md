# Agent Workflow Map + Stop Rules + Checkpoints + Workflow Test Set (гл. 11)

**Назначение:** превратить агента из «умного импровизатора» в управляемый процесс: вход → контекст → шаги → tools → проверки → stop rules → результат → handoff.
**Узлы гриллинга:** F1–F3, P3, P4, T1–T3, R3.

## Шаблон

```markdown
# Workflow — <агент>
Связано: 01, 02, 04, 06, 07

1. **Процесс:** …
2. **Цель:** …
3. **Кто/что запускает:** …
4. **Входные данные:** … · **Минимум для старта:** … (нет → status: blocked)
5. **Роль агента:** <кратко, ссылка на 02>
6. **Контекст перед стартом:** <что прочитать: 03, шаблоны, state>

## Шаги
### Step 1. <название>
- Input: …
- Action: …
- Output: …
- Check: …
- Tools: <только перечисленные>
(5–9 шагов)

## Stop Rules
Агент обязан остановиться, если:
1. **Нет обязательных входных данных** — что обязательно: … · что сказать: …
2. **Источники конфликтуют** — какие: … · приоритет: … · когда человек: …
3. **Нужен рискованный tool** — какой · риск · approval
4. **Нужно действие наружу** — отправка, публикация, изменение CRM или цены, удаление
5. **Задача вне роли** — что не делать · кому передать
6. **Проверка не прошла** — какая · что вернуть вместо «готово»
Формула: если X → остановись, объясни Y, запроси Z, предложи следующий безопасный шаг.

## Checkpoints
1. Перед стартом: вход, цель, источники, ограничения.
2. Перед tool use: нужен ли, есть ли права, не рискованный ли, нужен ли approval.
3. После tool use: ожидаемый результат? ошибка? полнота?
4. Перед внешним действием: что уходит наружу, нет ли обещаний, подтвердил ли человек.
5. Перед «готово»: критерий выполнен, источники указаны, открытые вопросы перечислены, handoff есть.
```

## Критерии качества (самопроверка гл. 11)
Понятно, что запускает · обязательный вход определён · есть роль и границы · контекст готовится до действия · 5–9 конкретных шагов вместо «проанализировать» · у каждого шага input/action/output/check · tools привязаны к шагам · есть stop rules · approval для рискованного · есть handoff. Три «нет» — workflow сырой.

## Красные флаги
Workflow как красивый список («проанализировать, сформировать, отправить») · 40 шагов · все tools на всех шагах · state только в чате · «готово» по словам агента без проверки · нет handoff · последний шаг «отправить клиенту» без approval.

## Принцип выбора глубины
Разовая простая задача → хорошего Task Brief достаточно. Повторяемая → workflow. Рискованная → строгий workflow: stop rules, approval, логи, проверка, handoff, rollback.
