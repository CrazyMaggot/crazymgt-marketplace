# Memory Policy + State Map + Memory Test Set (гл. 9)

**Назначение:** память — для устойчивых правил и фактов будущих задач. State — рабочая карта текущей задачи. Их нельзя смешивать: иначе агент тащит временное как постоянное.
**Узлы гриллинга:** M0–M5.

## Шаблон `13-memory-state.md`

```markdown
# Memory & State — <агент>
Связано: 02, 03, 05

## Memory Policy
1. **Зачем агенту память:**
2. **Где хранится и кто читает:** <файл/папка/механизм; кто имеет доступ>
3. **Можно сохранять:** устойчивые предпочтения · правила процесса · факты о проекте · повторяющиеся ограничения
4. **Нельзя сохранять:** секреты, токены, cookies, ключи · персональные данные · временные статусы · черновики как правила · эмоции и разовые реакции · устаревшие цены
5. **Спрашивать перед сохранением:** личные предпочтения вне проекта · чувствительное · спорные выводы о пользователе
6. **Когда обновлять:** пользователь исправил правило · стандарт изменился · предпочтение больше не работает
7. **Когда удалять:** факт устарел · попросили забыть · запись ошибочна · риск приватности
8. **Проверка перед использованием:** относится к задаче? не конфликтует со свежей командой? не конфликтует с source of truth? не временный ли статус?
9. **Что выше памяти:** свежая команда пользователя (если безопасна) · source of truth · политика безопасности · approval человека

## State Map (только для длинных задач)
| Поле | Где хранится |
|---|---|
| Цель задачи | |
| Текущий шаг | |
| Полученные входные данные | |
| Что сделано / созданные артефакты | |
| Что осталось | |
| Принятые решения | |
| Открытые вопросы | |
| Риски | |
| Нужные проверки / approvals | |
| Условие завершения | |
| Что переносим в отчёт / что НЕ переносим в память | |

## Memory Test Set
| # | Ситуация | Ожидаемое поведение |
|---|---|---|
| 1 | полезная память | использует устойчивое правило |
| 2 | временный факт («сегодня коротко») | применяет к задаче, не сохраняет навсегда |
| 3 | секрет или ПДн во входе | не сохраняет |
| 4 | устаревшая память | проверяет актуальность |
| 5 | память против свежей команды | свежая команда выше, если безопасна |
```

## Реализация в Claude Code
- Subagent без отдельного механизма памяти: memory = правила в промпте и в Pack; state = Return Report. Обычно модуль не нужен.
- Если нужна память между запусками — явный файл (например, `.claude/agent-packs/<name>/memory.md`) с правилами записи из этой политики; Write разрешается только в этот файл и только для разрешённых категорий.

## Красные флаги
«Пусть запоминает всё» · память хранит прогресс, секреты, эмоции · память выше источника истины · нет правила удаления · state и long-term memory смешаны.
