# Context Window Strategy + Compression Log + Isolation Rule (гл. 13)

**Назначение:** контекстное окно — рабочий стол агента, а не архив. Большое окно не заменяет структуру: шум в окне — это больше шума для модели.
**Узлы гриллинга:** W0–W4.

## Шаблон `14-context-window.md`

```markdown

Связано: 03, 05, 12, 13

| Шаг workflow | Что агент видит сейчас | Что держим снаружи | Что сжимаем (во что) | Что изолируем |
|---|---|---|---|---|
| 1 | | | | |

## Всегда в окне
<роль, границы, stop rules, формат результата — ядро промпта>

## Никогда не класть в окно целиком
<полные архивы, старые черновики, логи сборки, неиспользованные результаты поиска, ПДн без нужды>

## Правила сжатия (Compression Log)
Для каждого сжатия: что сжато → что сохранено → что потеряно намеренно → что нельзя потерять → где полный источник → риск сжатия.

## Isolation Rule
Выносим в отдельный поток, субагента или документ, если:
- разные роли спорят в одном окне (исследователь, автор, критик);
- есть риск смешать черновик и финал;
- есть опасное действие (отправка, удаление, платёж, публикация);
- источник слишком большой → source note + поиск фрагментов;
- нужна независимая проверка.
Формула: если кусок работы меняет роль, риск или источник доверия — вынеси его отдельно.

## Stop rule
<если контекст уходит от текущего шага или не хватает нужного фрагмента — остановиться>
```

## Реализация в Claude Code
- Изоляция = вызов субагента (Agent tool) с рабочей выжимкой вместо всей истории.
- Внешние большие источники — по пути и через Grep/Read фрагментов, а не целиком.
- Ядро промпта короткое, детали в Pack по ссылкам (это и есть стратегия на уровне сборки).
